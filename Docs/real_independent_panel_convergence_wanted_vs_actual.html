Wanted experiment versus actual implementation

This document compares the requested independent real dataset-panel convergence experiment with what the RiboUnmix repository now actually executes. It separates exact matches, intentional strengthening, implementation-specific choices, and remaining scientific limitations.

Short answer. The implemented experiment matches the central scientific design. It trains four genuinely separate models on non-overlapping dataset panels and evaluates their learned shared profiles on the same held-out transcripts. The implementation is now stricter than the original request: datasets from the same inferred publication/source family cannot be split across panels. The largest remaining caveat is that source families are inferred from dataset names rather than read from a curated metadata table.

1. First: which things are independent, and which are shared?

Independent across models

  • Selected Ribo-seq datasets
  • Source/publication families
  • Model parameters and optimizer states
  • Panel-specific gamma reference sets
  • Panel-specific eligible training transcript lists

Intentionally shared across models

  • Sequence encoder architecture and hyperparameters
  • Random seed and split-generation rule
  • The exact validation transcript IDs
  • The exact test transcript IDs
  • The evaluation and checkpoint-selection rules

This distinction is essential. The dataset panels must be disjoint; the held-out transcript IDs must be identical. Sharing test transcripts is not data-panel leakage—it is what makes (L_t^{(1)},ldots,L_t^{(4)}) directly comparable for the same biological sequences.

\[ \mathcal D^{(a)}\cap\mathcal D^{(b)}=\varnothing\quad(a\ne b), \qquad \mathcal T_{\mathrm{test}}^{(1)}=\cdots=\mathcal T_{\mathrm{test}}^{(4)}. \]

The implementation adds a second independence constraint. If (s(d)) is the inferred source family of dataset (d), then:

\[ s(d)=s(d')\;\Longrightarrow\;p(d)=p(d'), \]

so two conditions or replicates associated with the same publication are never placed in different panels.

2. What the implemented orchestrator actually does

1 · AuditValidate all 114 weighted, replica-aware parquet files.
2 · SummarizeCompute depth, coverage, support and replica-agreement statistics.
3 · PartitionAssign complete source families to four balanced panels.
4 · SplitCreate one common validation/test transcript split.
5 · TrainLaunch four independent model processes, one per available GPU slot.
6 · CompareAnalyze (L_t) from minimum-validation-loss checkpoints.

The orchestrator reuses the normal multidataset entrypoint. It does not duplicate the model, sampler, loss, gamma centering, optimizer, or prediction implementation.

4. How the actual dataset panels are built

  1. Validate each artifact. It must be a weighted replica-aware parquet with transcript ID, consensus profile, raw replicas, and a strictly positive retained weight.
  2. Apply sequence eligibility. Dataset statistics include only transcripts in the eligible sequence universe, including the configured CDS-length rule.
  3. Calculate observed statistics. For every dataset, the code measures median read density, median positive-codon coverage, eligible-transcript count and replica PCC.
  4. Construct source families. An explicit non-empty source_identifier is respected. Otherwise, the dataset-name author_year prefix is used.
  5. Keep the family atomic. The algorithm moves the complete source group, not individual conditions.
  6. Balance under exact capacities. It uses four rank bins for depth and coverage, a replica-quality category, standardized observed features, and exact panel capacities.
  7. Improve balance safely. Only equal-size source groups can be swapped after initial assignment, so neither panel size nor source atomicity can be broken.

Why the algorithm is not simple round-robin anymore. Once a nine-dataset publication family must remain intact, assigning one dataset at a time could violate independence. The implementation therefore assigns source groups under capacity constraints. This is an intentional difference from the simplest algorithm proposed in the original prompt.

5. Wanted transcript split versus actual transcript split

Let (K_t^{(p)}) be the number of positive eligible dataset observations for transcript (t) inside panel (p). The common evaluation universe is:

\[ \mathcal T_{\mathrm{common}} =\left\{t:\min_{p\in\{1,2,3,4\}}K_t^{(p)}\ge2\right\}. \]

The actual clean dry run found 15,929 transcripts satisfying this rule. The split generator then selected:

  • 1,593 validation transcripts (approximately 10%);
  • 1,593 test transcripts (approximately 10%);
  • panel-specific training lists from all remaining sequence-eligible transcripts with (K_t^{(p)}\ge2).

How held-out transcripts are sampled

For each common transcript, the implementation computes the median of its stored positive local reliability weights across all selected datasets. It converts this score into one of ten rank bins and crosses it with the established CSS-count category. Validation is sampled proportionally from these strata; test is sampled from the remaining transcripts using the same strata.

Important implementation-specific detail. Transcript length is checked for sequence eligibility and recorded, but it is not currently an additional split stratum. The actual stratification is reliability rank bin × CSS bin. This is acceptable under the original “reuse established stratification where possible” wording, but it is not identical to a hypothetical reliability × CSS × length design.

6. Training and evaluation contract

Forced training settings

  • transcript_grouped_multidataset_pairs
  • minimum_positive_datasets_per_transcript=2
  • loss.sample_reduction=transcript_balanced
  • model.mass_conservation=false
  • learned alpha using the current production configuration
  • raw replicas retained for NB2

Forced comparison settings

  • fixed-reference gamma centering
  • reference set = exactly that panel
  • uniform (pi_d=1/|\mathcal D^{(p)}|)
  • prediction only from best_val_loss
  • prediction split = common test transcripts
  • no analysis-time renormalization of (L_t)

Reliability weights are train-only calibrated

The default experiment mode fits each dataset's depth reference ( au_d) and raw-weight normalization median only from that panel's training transcript IDs. These references are frozen for validation and test. The manifest explicitly verifies:

\[ N_{\mathrm{heldout\ rows\ used\ for\ fitting}}=0. \]

The historical precomputed weight column remains available only through the explicit --reliability-weight-mode=stored compatibility option. It is no longer the default for this experiment.

What happens after training

  1. Each panel must produce exactly one prediction manifest for best_val_loss.
  2. The launcher verifies that it is a test-split artifact and that its transcript-ID hash equals the common test hash.
  3. The analysis verifies identical transcript sets and identical (L_t) values across duplicate dataset rows within a panel.
  4. For every transcript and all six panel pairs, it computes PCC, Spearman correlation and mean-one RMSE.
  5. It writes long-form tables, summary quantiles, representative profiles, agreement distributions and a 4×4 median-agreement matrix.

7. The differences that matter scientifically

  • Stronger Publication families are atomic. The original core equation only required dataset-name disjointness. The current code also prevents conditions/replicates from an inferred common source from crossing panels.
  • Different Greedy source-group balancing replaces simple per-dataset round-robin. This is required to preserve source independence while still achieving exact capacities.
  • Different The source unit is inferred. The fallback takes the author_year prefix from the dataset name. This is reproducible, but not equivalent to curated publication/laboratory metadata.
  • Different Split reliability uses stored weights only for stratification. These scores choose a diverse held-out set; train-only fitted references are separately used to construct loss weights during the experiment.
  • Different Length is not a split stratum. It remains an eligibility rule and an analysis field.
  • Stronger Cached quality summaries carry provenance. A cache is rejected if weighted artifacts, the sequence file, or maximum-CDS eligibility changed.
  • Intentional scope No architectural control models are launched. This agrees with the original instruction not to implement the gamma fingerprint, saturation series, or additional architecture baselines in this task.
Remaining independence limitation. Zero source-family crossings does not prove zero shared laboratory, protocol, sample, or consortium origin when those relationships are not encoded in dataset names. A publication-curated metadata table would be required to enforce those stronger notions of independence. The present code should therefore claim dataset-disjoint and inferred-source-family-disjoint panels, not universally metadata-independent panels.
No scientific convergence result exists from the dry run. The verified numbers above concern panel construction and split integrity. PCC, Spearman and RMSE between learned (L_t) profiles only exist after all four GPU trainings finish successfully.
