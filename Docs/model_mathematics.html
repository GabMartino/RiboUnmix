RiboUnmix — current data and objective

A source-aligned description of the data table, transcript weights, transcript split, group-aware optimizer batching, replica-aware negative-binomial/Pearson objective, mass-free prediction, fixed-reference gamma gauge, and loss reduction currently implemented in the repository.

The numerical dataset summary below was regenerated from the checked-out weighted HEK parquets and Datasets/data/sequence/MANE.selection.sequence_embeddings_with_css.parquet. The equations follow the current code and the active mass-free training configuration with model.mass_conservation=false. The conserved path is documented only as an ablation. Start here: the whole idea without equations

One-sentence version: the model learns where ribosomes pile up along a transcript, allows each experiment to adjust that shared shape, scores the prediction against the raw experimental repeats and their average, and gives every transcript one equal vote in the default loss.

Transcript

One biological sequence—think of it as one recipe.

Dataset

One experiment that measured many recipes under its own laboratory conditions.

Replica

A repeated measurement inside the same experiment. It is not a new dataset.

Pair

One transcript measured in one dataset. This is one physical training row.

Two kinds of “average” appear repeatedly: first, raw replicas are averaged to make a consensus profile for shape correlation. Later, losses are averaged according to the selected balancing rule. These are different operations.

Scope

This document intentionally starts before the neural-network architecture. It explains the data, splitting, logical batches, memory-bounded execution, grouped accumulation, and optimized objective. It also explains the gamma-centering gauge because this determines how the dataset-specific correction is interpreted during both training and inference. It includes the essential two-branch model picture, but deliberately leaves out layer-by-layer tensor plumbing, optimizer internals, and plotting code.

The basic observation is a transcript–dataset pair. A transcript can occur in many datasets, and each pair can contain several raw biological replicas. The pair is the unit that receives a local reliability weight and the unit whose replica losses are averaged.

1. Data representation

Plain language: the model does not receive “one transcript” as one sample. It receives one measurement of that transcript from one dataset. If the transcript was measured in five datasets, it can contribute five pair rows. Each row still carries all raw repeated measurements from its own dataset.

1.1 Indices and notation

Let \(d\) identify a dataset, \(t\) identify a transcript, \(r\) identify a raw replica within one dataset–transcript pair, and \(i\) identify a codon position. Let \(\mathcal D\) be the set of datasets, \(\mathcal T\) the set of transcript IDs, and \(L_t\) the number of codon positions in transcript \(t\). The symbol \(R_{dt}\) is the number of valid raw replicas for pair \((d,t)\); it is the number of replica entries marked true by the replica mask.

The raw count at one position is \(y_{dtri}\). The consensus profile stored in the batch is \(y_{dti}\), and \(m_{dti}\) is the consensus position-validity mask: it is one for a real codon position with a finite target and zero for padding or a non-finite target. The raw-replica mask \(m_{dtri}\) is one when replica \(r\) is present and its position \(i\) is valid, and zero otherwise. The observed profile is never allowed to contain negative counts.

2. Transcript reliability weights

Plain language: a reliability weight answers “how much should I trust this dataset's profile for this transcript?” The main evidence is now the actual number of reads per codon. Coverage remains a smaller check that the reads are spread across the transcript rather than concentrated at a few codons. The final value is not a probability: 1.25 is a perfectly valid weight.

2.1 Pair-local filtering

The weighting script is Datasets/data/weight_hek_riboseq_codon_replicas.py. Its add_weights() function validates each consensus profile before computing any weight. A profile is rejected with an error if it is nested, non-finite, or contains a negative count. An empty profile, or a non-empty profile with no positive codon, is not eligible and is removed from that dataset's output. A non-empty profile is eligible only when its positive-codon coverage and total read count are both greater than zero.

Eligible filtering is applied to the pair \((d,t)\), not globally to \(t\). If transcript \(t\) is zero in dataset \(d_1\) but positive in dataset \(d_2\), only the row \((d_1,t)\) is removed. Empty and zero-coverage rows are always physically removed; there is no active keep-zero compatibility path. The preprocessor, split loader, training dataloader, and loss reducer all enforce the same contract: every materialized pair has a finite, strictly positive reliability weight.

2.2 The recommended SNR-motivated equation

For an eligible consensus profile, define the positive-codon coverage \(C_{dt}\), the total read count \(Q_{dt}\), and the mean read density \(D_{dt}\) as follows. The symbol \(L_t\) is the number of profile positions and \(\mathbf 1[\cdot]\) is one when its condition is true and zero otherwise.

$$ C_{dt}= \frac{1}{L_t}\sum_{i=1}^{L_t}\mathbf 1[y_{dti}>0], \qquad Q_{dt}=\sum_{i=1}^{L_t}y_{dti}, \qquad D_{dt}=\frac{Q_{dt}}{L_t}. $$

Let \(\mathcal E_d\) be the eligible transcript IDs in dataset \(d\). The reference density \(\tau_d\) is, by default, the ordinary median of their positive read densities.

$$ \tau_d=\operatorname{median}_{u\in\mathcal E_d}D_{du}, \qquad R^{\mathrm{depth}}_{dt}= \frac{\sqrt{D_{dt}}}{\sqrt{D_{dt}}+\sqrt{\tau_d}}. $$

This depth score is zero at zero reads, exactly 0.5 at the typical density \(D_{dt}=\tau_d\), increases with actual density magnitude, and approaches one without crossing it. The new raw score gives depth the primary 70% role and uses coverage linearly for the remaining 30%.

$$ w^{\mathrm{raw}}_{dt}=0.70R^{\mathrm{depth}}_{dt}+0.30C_{dt}. $$

raw reliability = 70% saturating depth score + 30% linear coverage

Small numerical example: if coverage is 0.25, then its coverage score stays 0.25. If read density equals \(\tau_d\), the depth score is 0.5, so raw_weight = 0.70 × 0.5 + 0.30 × 0.25 = 0.425.

2.3 Why depth is primary and coverage stays linear

Coverage and depth are related: as more reads are collected, more codons are likely to be observed at least once. But they answer different questions. Density measures how much sampling information exists; coverage measures how broadly it is spread. Coverage is already bounded and naturally saturates near one. Applying a square root to it would boost every sparse value because \(\sqrt C>C\) for \(0<C<1\); for example, 10% coverage would be inflated from 0.10 to about 0.316.

Depth has the stronger statistical motivation for a square-root response. Under a Poisson approximation, \(\operatorname{SD}(Y)=\sqrt\mu\), so signal-to-noise grows like \(\sqrt\mu\). Under the overdispersed NB2 model, \(\operatorname{Var}(Y)=\mu+\alpha\mu^2\), so gains should become sublinear at high depth. The chosen transform has that qualitative shape. The 70/30 coefficients are still a modeling choice, not a unique theorem; the separate replica-reproducibility utility exists to test whether the score actually predicts repeatability without fitting coefficients to validation loss.

2.4 Median normalization and use in the loss

The script then divides by the ordinary numerical median of the raw scores in the same eligible dataset. In the standalone default workflow no training-only references are passed, so both \(\tau_d\) and this denominator are fitted from the complete eligible dataset. The final weight is

$$ w_{dt}=\frac{w^{\mathrm{raw}}_{dt}} {\operatorname{median}_{u\in\mathcal E_d}\left(w^{\mathrm{raw}}_{du}\right)}. $$

final reliability = raw reliability ÷ the typical raw reliability in that dataset

The normalization bounds are disabled. Therefore \(w_{dt}\) is strictly positive but is not restricted to \([0,1]\); the table above contains values above one. A weight of 1 means “at this dataset's median,” 1.25 means “25% above that median scale,” and 0.5 means “half that median scale.” In the default transcript-balanced loss, \(w_{dt}\) compares the available dataset observations inside the same transcript. It does not change the profile, replica count, NB dispersion, or PCC calculation itself.

What median normalization can and cannot change: in dataset-balanced mode, the common median divisor cancels inside each dataset's weighted mean. In the default transcript-balanced mode it generally does not cancel, because one transcript's inner mean compares weights from different datasets, each with its own median. The normalization therefore puts those dataset-local reliability scores onto a comparable “typical value = 1” scale. It also affects the split-only score \(q_t=\operatorname{median}_d(w_{dt})\).
Normalization-protocol caveat: the checked-in weighted parquets and their manifest predate the explicit mode field and contain the historical formula described below. The preprocessing code now defaults newly regenerated artifacts to snr_depth_coverage; existing files are not silently reinterpreted. For a future strict final train/validation protocol, fit both \(\tau_d\) and the raw-weight median on training IDs only and apply those two frozen values to validation and test IDs. Both references can already be supplied externally by the weighting functions.

2.5 Explicit legacy ablation

legacy_coverage_density_rank exactly reproduces the prior equation. It first computes the within-dataset percentile rank of log1p(read_density), then uses

$$ P_{dt}=\operatorname{rankPct}_{u\in\mathcal E_d}\!\left(\log(1+D_{du})\right), \qquad w^{\mathrm{raw,legacy}}_{dt}=0.70\sqrt{C_{dt}}+0.30P_{dt}. $$

This mode is retained only for reproducibility and ablation. A percentile rank depends on ordering, not the magnitude of depth: ranking \(D\), \(\sqrt D\), or \(\log(1+D)\) gives the same order apart from ties and numerical details. That is why the new mode does not use percentile ranking at all.

3. Transcript-level splitting

Plain language: validation is the exam. To compare runs fairly, every run gets the same exam questions: transcript IDs that exist in every dataset of the fixed 114-dataset master collection. Reliability bins and CSS classes make the exam representative; they do not give the “best” transcripts preferential admission.
The split in four steps:
  1. Build one master union of every retained transcript in the 114 weighted datasets.
  2. Allow validation only from the master intersection: transcripts retained in all 114.
  3. Choose 10% of that intersection across reliability deciles and CSS-count classes.
  4. Freeze those transcript IDs as validation; every other master-union ID is training.
Changing only experiment.dataset does not redraw validation.

3.1 The split unit is a transcript, not a pair

The implementation is fixed_common_validation_split() in main_ribounmix_multidataset.py. It assigns the transcript ID \(t\), never an individual dataset–transcript row. Once \(t\) is assigned to validation, all of its rows in every selected experiment dataset are validation rows. The same transcript cannot be used for training in another dataset.

split.master_dataset_universe: all defines a fixed master collection. Let \(\mathcal D_{\mathrm{master}}\) be those 114 datasets and let the complete transcript pool be the sequence-overlapping union

$$ \mathcal U= \mathcal T_{\mathrm{sequence}}\cap \bigcup_{d\in\mathcal D_{\mathrm{master}}} \{t:(d,t)\text{ is retained}\}. $$

Rows with zero codon coverage were physically removed during preprocessing. Therefore a retained row represents a real positive-coverage profile, and every retained weight is finite and strictly positive.

3.2 One fixed validation panel from the master intersection

The validation candidates are not recomputed from the datasets selected for an individual run. They are computed once from the intersection of the entire master collection:

$$ \mathcal C_{\mathrm{master}}= \mathcal T_{\mathrm{sequence}} \cap\bigcap_{d\in\mathcal D_{\mathrm{master}}} \{t:(d,t)\text{ is retained and }w_{dt}>0\}. $$

Only IDs in \(\mathcal C_{\mathrm{master}}\) can enter validation. Consequently the same fixed validation IDs are available in any experiment-dataset subset drawn from the master collection. A missing weight column, duplicate transcript ID, or non-finite, zero, or negative weight is an explicit error; the split code does not impute it.

Why this is useful: a two-dataset run and a 114-dataset run evaluate the same biological transcripts. Changing experiment.dataset therefore changes the observations used for fitting, not the identity of the validation panel. The panel changes only when the master universe, source files, random seed, or split configuration changes.

3.3 Reliability and CSS jointly make validation representative

CSS means a conserved stalling site: an annotated codon where ribosome stalling may be biologically interesting. CSS is used here only as a label for maintaining a similar mixture of transcripts with zero, one, a few, or many annotated sites.

Each common candidate has one local reliability weight per master dataset. For split selection only, the code summarizes those 114 values by the ordinary median

$$ q_t=\operatorname{median}_{d\in\mathcal D_{\mathrm{master}}} w_{dt}. $$

The candidates are ranked by \(q_t\) and divided into ten near-equal reliability bins. Independently, the CSS annotation in the sequence parquet is reduced to one of four count classes: no CSS, one CSS, two or three CSS, or at least four CSS sites. The actual stratification key is the pair

$$ s_t=(\text{reliability-decile}(q_t),\ \text{CSS-count-class}(t)). $$

The requested validation total is distributed proportionally over these joint strata by largest remainder, and IDs are sampled uniformly within each stratum using numpy.random.default_rng(experiment.seed). CSS is thus a suggestion about the composition of validation: it helps preserve the master candidate pool's CSS mixture. It does not create a CSS benchmark, reserve a CSS percentage, or make a CSS-positive transcript automatically enter validation.

This is also stratification by reliability, not probability-proportional-to-weight sampling. Large \(q_t\) does not itself give a transcript a larger selection probability. The point of the deciles is to include weak, middle, and strong profiles rather than fill validation with only the most reliable profiles.

The split score \(q_t\) is used only for choosing a representative validation set. It does not overwrite the pair weights. Later, the loss still uses each original \(w_{dt}\) to weight dataset observations inside the selected sample reducer. In the default transcript-balanced mode, those weights compare datasets only within the same transcript.

3.4 Validation size and the different training sizes

The configured fraction applies to the common candidate set, not separately to every dataset and not to the union:

$$ n_{\mathrm{val}}=\operatorname{round} \left(|\mathcal C_{\mathrm{master}}|\,f_{\mathrm{val}}\right), \qquad f_{\mathrm{val}}=0.10. $$

After the fixed set \(\mathcal V\) is sampled, training is simply the rest of the master union:

$$ \mathcal T_{\mathrm{train}}=\mathcal U\setminus\mathcal V. $$

For a selected dataset \(d\), the dataloader materializes only IDs for which that dataset actually has a row:

$$ \mathcal T^{\mathrm{train}}_d= \mathcal T_{\mathrm{train}}\cap\{t:(d,t)\text{ is retained}\}, \qquad \mathcal T^{\mathrm{val}}_d=\mathcal V. $$

This is how unequal dataset sizes are handled. Every selected dataset contributes the same 714 validation transcript IDs, while its training count is all of its own remaining rows before grouped-sampler support filtering. No transcript is discarded merely to force a small dataset's raw split size to match a larger dataset. For the multidataset training sampler, however, a training transcript must then have a positive eligible row in at least two selected datasets; singleton rows are excluded before packing. The default transcript-balanced loss prevents an admitted transcript from receiving more outer mass merely because more datasets contain it.

Consequently, validation_frac: 0.1 does not mean “ten percent of every selected dataset.” It means ten percent of the fixed master-common candidate panel. A selected dataset with 10,000 retained rows and one with 16,000 retained rows both validate on the same 714 transcript IDs, then use their own available non-validation rows for training.

4. Grouped logical batches, execution forwards, and optimizer updates

Plain language: imagine putting every measurement of one transcript into a folder. The sampler places several complete folders in a logical batch. If that logical batch is too large for memory, execution microbatching opens only a few complete folders at a time. Gradient accumulation then decides how many complete logical batches contribute before the optimizer changes the parameters. These are three different controls.

4.1 data.batch_size is a per-dataset quota

The basic in-memory row is \((t,d)\), not just transcript \(t\). For every sampler-eligible transcript define its complete group

$$ G_t=\{(t,d):d\in D_t^+\}, \qquad K_t^+=|D_t^+|\ge2. $$

The grouped sampler never splits \(G_t\). The configured value data.batch_size = B_d is now the maximum number of pair rows from each represented dataset in one logical grouped batch:

$$ \#\{(t,d)\text{ in one rank's logical batch}\}\leq B_d \quad\text{for every dataset }d. $$

With \(D\) represented datasets, the nominal total pair-row ceiling on each GPU is

$$ B_{\mathrm{pair,max}}=B_dD. $$

This does not assign one dataset to one GPU: every rank normally sees rows from all datasets. Atomic groups are packed greedily subject to every dataset quota. When support differs across transcripts, some quotas can be underfilled, so the actual row total may be less than \(B_dD\). A duplicate \((t,d)\) row is rejected because the data model expects exactly one row per transcript–dataset pair.

The positive-support test and duplicate check happen before this packing and before the non-mutating accumulation preview. The planner therefore measures only groups that can actually train; excluded \(K^+=0\) and \(K^+=1\) transcripts occupy no quota.

Important naming clarification. In the implementation, data.batch_size is not literally a global tensor batch-size field. It is a per-dataset limit on pair rows. If every admitted transcript has one row in every selected dataset, the number happens to equal the number of unique transcripts. With missing dataset observations, it is only a quota, and the actual number of unique transcripts is measured by the sampler rather than assumed.

4.3 What target_unique_transcripts_per_optimizer_step does

The short version: batch_size: 32 says approximately how many different transcripts can be placed in one complete logical batch when dataset support is rectangular. target_unique_transcripts_per_optimizer_step: 32 says “do not change the model parameters until approximately 32 different transcripts have contributed.” With 32 transcripts per full logical batch, the typical accumulation factor is one.

An optimizer update is the moment at which the optimizer finally changes the model parameters. A forward pass calculates predictions and a loss; a backward pass calculates gradients. Gradient accumulation can perform several forward/backward calculations, add their gradients together, and postpone the parameter change until all of them have contributed.

The target counts unique transcript identities, not pair rows. If transcript t1 has observations in 20 datasets, its 20 pair rows still count as one transcript toward the target. The purpose is to keep approximately the same amount of biological sequence diversity in an optimizer update when the number of selected datasets or the pattern of dataset support changes.

The code cannot assume that batch_size: 32 always produces exactly 32 transcripts. Complete transcript groups have different numbers of dataset rows, and the last logical batch can be smaller. Before training, it therefore makes a non-mutating preview of the real grouped sampler and records the number of unique transcripts in every previewed logical batch. The configured accumulation_statistic: median selects the middle of those observed counts as the estimate of a typical logical batch. In plain terms:

$$ \text{typical transcripts per logical batch} =\operatorname{median}(\text{observed transcript counts}). $$

It then divides the desired transcript target by that typical count and rounds upward, because the number of logical batches must be a whole number:

$$ \text{required logical batches per optimizer update} = \left\lceil \frac{\text{desired unique transcripts per optimizer update}} {\text{typical unique transcripts per logical batch}} \right\rceil. $$

For the current one-GPU, two-dataset configuration, the preview median is 32 unique transcripts per logical batch and the desired target is 32. Therefore:

$$ \left\lceil\frac{32\text{ desired transcripts}} {32\text{ transcripts per logical batch}}\right\rceil =1\text{ logical batch per optimizer update}. $$

That logical batch has 32 rows from each of the two datasets: 64 pair rows. The word “approximately” matters for partially supported panels because greedy packing can produce a different number of transcript groups.

max_accumulate_grad_batches: 32 is merely a safety ceiling on the answer. It does not request 32 batches. The current calculation requests one, so the ceiling does nothing. If the calculation requested 40, the runtime would use 32 and warn that the desired transcript target cannot be reached.

auto_accumulate_grad_batches: true means the preview performs this calculation automatically. The resolved whole-number accumulation factor is saved in the grouped optimizer plan. When execution_microbatching.enabled: false, it becomes Lightning's trainer.accumulate_grad_batches. When execution microbatching is enabled, the Trainer value is deliberately set to 1 and the Lightning module manually counts the resolved number of logical batches. This distinction is necessary because Lightning sees execution chunks as loader batches, while the optimizer plan is defined in logical transcript groups.

4.4 How logical batching, execution chunks, accumulation, and gamma reference chunks connect

These settings answer different questions. Reading them from left to right prevents the word “batch” from hiding four different units:

For a logical batch containing transcript groups \(G_1,\ldots,G_G\), the execution packer greedily starts a new forward before adding the next complete group if any enabled limit would be exceeded:

  • max_pair_rows_per_forward: 512 limits pair rows;
  • max_padded_codon_tokens_per_forward: 256000 limits pair rows × longest CDS length, an estimate of padding memory;
  • max_transcript_groups_per_forward: null disables a separate group-count limit.

The limits are soft for one indivisible group: if a single transcript has more than 512 dataset rows, or its padded profile alone exceeds 256,000 tokens, that group is emitted intact. Gradient accumulation cannot repair a split transcript, so preserving group atomicity has priority over these memory budgets.

For the next equation, \(G\) is the total number of transcript groups in the original logical batch, \(G_c\) is the number placed in the current execution chunk, \(L_c\) is that chunk's transcript-balanced mean loss, and \(A\) is the resolved number of logical batches accumulated per optimizer update. The manual backward pass uses

$$ L_c^{\mathrm{backward}}=L_c\frac{G_c}{G}\frac{1}{A}. $$

Summing chunks reconstructs the exact transcript-balanced logical-batch loss; summing \(A\) logical batches reconstructs the configured accumulation window. Clipping with gradient_clip_val: 1.0 and gradient_clip_algorithm: norm happens once, after all those gradients exist, immediately before the optimizer step. Trainer-level clipping is therefore null, avoiding partial-chunk or duplicate clipping. Execution microbatching currently requires loss.sample_reduction: transcript_balanced; the runtime rejects another mode because the \(G_c/G\) reconstruction would not be the correct weighting for it.

Numerical examples for complete support. With two datasets, batch_size: 32 means 32 groups and 64 pair rows, so the 512-row limit leaves the logical batch in one forward. With 20 datasets it means 32 groups and 640 rows; ignoring the token limit, the packer can emit 25 groups/500 rows and then 7 groups/140 rows. With 114 datasets it means 32 groups and 3,648 rows; the 512-row limit normally fits four complete 114-row groups per forward. In every case the planner still sees 32 logical groups and resolves \(A=\lceil32/32\rceil=1\). Partial support and CDS lengths can change the actual chunking, which is why runtime statistics—not \(32D\) alone—are used.

gamma_centering.reference.chunk_size: 32 is orthogonal to all of this. For each transcript in an execution forward, fixed-reference centering internally evaluates at most 32 reference dataset identities at a time, concatenates their differentiable raw log-gamma results, and computes the same weighted center. It does not mean 32 transcripts, 32 pair rows, or 32 accumulated batches, and changing it must not change gamma or \(\mu\) beyond floating-point tolerance. Because fixed-reference centering uses the checkpointed panel rather than co-resident rows, subdividing a logical batch does not change its gauge.

There is nevertheless a compute connection. If one execution chunk contains \(G_c\) distinct transcripts and the fixed panel contains \(R\) datasets, the reference path evaluates \(G_cR\) raw reference gamma profiles in total. With chunk size \(C=32\), the dataset dimension is processed in \(\lceil R/C\rceil\) internal pieces (the final piece may be smaller). Thus lowering the execution limits reduces how many transcripts are live at once; lowering reference chunk_size reduces how many reference datasets are live per internal evaluation. Neither changes the observations in the logical batch, the accumulation target, or the gamma equation.

What happens when the selected dataset count grows? For complete support, changing from \(D=2\) to \(D=114\) increases a logical batch from \(32\times2=64\) to \(32\times114=3648\) requested pair rows and, because reference.dataset_names: null, increases the fixed reference panel from 2 to 114 datasets. Execution microbatching controls the requested-row memory; reference chunk_size: 32 controls the internal reference-panel memory. The target remains 32 unique transcripts per optimizer update because it counts biological transcripts, not datasets or pair rows.

4.5 DDP: per-rank versus global targets

The two mechanisms do not currently run together. Grouped sampling and the accumulation planner support DDP, but execution_microbatching.enabled: true is currently single-process only. The runtime raises if the configured world size is greater than one. To launch DDP, explicitly set training.execution_microbatching.enabled=false; then Lightning performs the resolved accumulation automatically and each complete logical batch is one forward on its rank. The calculations below describe that DDP configuration.

The sampler first constructs one deterministic global list of complete logical batches, then assigns whole logical batches round-robin to ranks. If necessary, it adds at most one fewer batches than the number of ranks so every rank executes the same number of DDP collectives. Transcript groups are never divided between ranks.

Here a rank means one DDP training process, normally attached to one GPU, and the world size means the total number of those processes. For example, two GPUs normally give two ranks and a world size of two.

With the active target_scope: per_rank, the configured value 32 applies separately to every rank. In the following equation, local target means the desired unique-transcript count on one rank, while configured target is the value written in the YAML:

$$ \text{local target on each rank}=\text{configured target}=32. $$

Thus a two-rank job targets approximately 64 transcripts globally. This keeps local work per GPU stable but means changing the number of GPUs changes the global effective batch. The available global scope instead uses

$$ \text{local target on each rank}= \max\left(1,\left\lceil \frac{\text{configured target}} {\text{number of DDP ranks}} \right\rceil\right). $$

This is preferable when the total optimizer batch should remain approximately invariant to GPU count. The scope does not affect group integrity.

4.7 Exactness and diagnostics

The planner stabilizes the approximate number of transcripts per update; it does not in general construct a mathematically exact concatenated large batch. Each accumulated logical-batch mean gives one gradient contribution. If logical batches contain different numbers of transcripts, different represented datasets, or different reliability-weight sums, averaging their gradients is not identical to evaluating the loss once over their concatenated rows. The epoch-zero preview can also differ slightly from later shuffled epoch packings.

For that reason the runtime records pair rows, unique transcripts, datasets per transcript, the coefficient of variation of transcript counts, the resolved accumulation factor, and estimated optimizer steps. These diagnostics reveal whether the target is a good approximation. The mechanism does not alter the loss equation, learning rates, weight decay, atomic grouped sampler, or validation split.

For transcript-balanced loss, a complete transcript is exact inside one execution chunk because its group is atomic. The \(G_c/G\) scaling also makes multiple execution chunks exactly reconstruct their original logical batch. Across logical batches, however, each batch mean still receives equal accumulation weight. Therefore an optimizer window is an exact equal mean over all its transcripts only when its logical batches contain the same transcript count. The logged unique_transcripts_per_microbatch name is retained for compatibility; it refers to logical sampler batches in the grouped plan, and its epoch coefficient of variation quantifies this remaining approximation.

5. What the model predicts and why gamma is centered

5.1 The prediction in plain language

Think of two transparent layers. The blue layer, \(L^{\mathrm{bio}}\), is the sequence-driven ribosome pattern shared by every dataset. The orange layer, \(\gamma\), says how one particular dataset reshapes that shared pattern. The layers are multiplied directly and then multiplied by the observed mean read depth \(S\). There is no final normalization of \(\gamma L^{\mathrm{bio}}\). Consequently, the model can change both the codon-by-codon shape and the total predicted mass relative to its observed scale anchor.

Lbio

Shared relative ribosome load along the transcript. Its valid-position mean is one.

gamma (γ)

Positive dataset-specific reshaping. One means “leave the shared shape unchanged” at that position.

scale (S)

The observed average target count for this pair. It is supplied, not learned.

prediction (μ)

The NB2 mean at every codon: the direct product S × gamma × Lbio, without forcing its mean back to S.

dispersion (α)

How much count noise NB2 allows beyond a Poisson model. It changes uncertainty, not μ.

rho (ρ)

A bounded display of Lbio, equal to Lbio/(1+Lbio); high values mark high shared load.

More precisely, the biological branch produces a positive mean-one profile \(L^{\mathrm{bio}}_{ti}\). The centered dataset branch produces positive \(\gamma_{dti}\). With valid-position mean denoted by \(\operatorname{mean}_i\), the active mass-free prediction is

$$ S_{dt}=\operatorname{mean}_i(y_{dti}),\qquad h_{dti}=\gamma_{dti}L^{\mathrm{bio}}_{ti},\qquad \boxed{\mu_{dti}=S_{dt}\gamma_{dti}L^{\mathrm{bio}}_{ti}}. $$

predicted counts = observed scale anchor × shared biology × dataset correction

It follows that

$$ \operatorname{mean}_i(\mu_{dti}) =S_{dt}\operatorname{mean}_i\!\left(\gamma_{dti}L^{\mathrm{bio}}_{ti}\right), $$

and therefore the predicted-to-observed mass ratio over valid codons is

$$ \frac{\sum_i\mu_{dti}}{\sum_i y_{dti}} =\operatorname{mean}_i\!\left(\gamma_{dti}L^{\mathrm{bio}}_{ti}\right). $$
What “mass-free” means here: the prediction is no longer forced to have exactly the observed profile sum. The NB2 likelihood can penalize a prediction whose aggregate level is wrong, rather than receiving exact agreement by construction. However, \(S_{dt}\) still comes from the observed target, so this is not a fully independent transcript-abundance model. It is a target-derived scale anchor followed by a learned, unconserved multiplicative profile.

Why the strict normalization was removed

The former mass-conserving option used

$$ \mu^{\mathrm{conserved}}_{dti} =S_{dt}\frac{\gamma_{dti}L^{\mathrm{bio}}_{ti}} {\operatorname{mean}_j(\gamma_{dtj}L^{\mathrm{bio}}_{tj})}. $$

This guaranteed \(\sum_i\mu_{dti}=\sum_i y_{dti}\) before the likelihood was evaluated. That is unnecessarily restrictive when experimental bias can change the number of reads assigned to a transcript—as it explicitly does in the synthetic bias data, whose counts are not renormalized after applying a bias. The active mass-free form lets the model be judged on both local allocation and aggregate magnitude. The conserved equation remains useful only as a controlled ablation.

5.2 Why a gamma gauge is needed

The prediction separates a transcript-shared biological profile L_bio from a dataset-specific positive correction gamma. Before the target-derived mean scale is applied, their product defines the position shape:

$$ h_{dti}=\gamma_{dti}L^{\mathrm{bio}}_{ti}. $$

A position pattern common to every dataset could still be represented partly in \(L^{\mathrm{bio}}\) and partly in every dataset's \(\gamma\). The fixed-reference center removes this cross-dataset attribution ambiguity by making the weighted geometric mean of reference gamma equal one at every codon.

The positional geometric-mean-one rule is also retained:

$$ \operatorname{mean}_i\log\gamma_{dti}=0 \quad\Longleftrightarrow\quad \operatorname{geomean}_i\gamma_{dti}=1. $$
Important change in interpretation: under the mass-free equation, multiplying a complete gamma profile by a constant would change \(\mu\). The positional rule is therefore no longer removing an invisible symmetry created by final mass normalization. It is now an explicit identification and interpretability constraint: gamma describes relative position-specific bias rather than becoming a free pair-wide abundance multiplier. This keeps “gamma = 1” as a meaningful neutral reference.

This gauge does not secretly restore mass conservation. Even though \(\operatorname{geomean}_i(\gamma_{dti})=1\) and \(\operatorname{mean}_i(L^{\mathrm{bio}}_{ti})=1\), in general

$$ \operatorname{mean}_i\!\left(\gamma_{dti}L^{\mathrm{bio}}_{ti}\right)\ne1. $$

The arithmetic mean of the product depends on gamma's variation and on where that variation aligns with the shared biological profile.

The unconstrained dataset branch produces the raw log correction

$$ a^{\mathrm{raw}}_{dti}=q_{dti}+\log(\gamma_{\mathrm{init}}), \qquad \gamma_{\mathrm{init}}=1. $$

The raw score is not clipped. Centering is applied to this log score before the exponential. The resulting \(\gamma L^{\mathrm{bio}}\) product is then used directly; it is not subsequently normalized.

5.3 The fixed reference panel

With mode: fixed_reference, the center is not estimated from the rows in the logical batch or execution forward. By default the reference panel \(\mathcal R\) contains every dataset in experiment.dataset. A non-null reference.dataset_names can select a duplicate-free subset, but every named reference must still be one of the experiment datasets.

The resolved panel IDs, its weights, the selected-dataset IDs used to define the dataset embedding gauge, and a manifest hash are stored in the model state. Loading a compatible checkpoint therefore restores the training reference panel. Old checkpoints without these persistent reference buffers are rejected in fixed-reference mode rather than silently receiving a new gauge. The complete model state is loaded strictly as well: missing or unexpected parameter/buffer keys are an error, so there is no partial legacy load path.

For every distinct transcript requested in a forward pass, the code takes one canonical set of transcript-invariant inputs—codon IDs, masks, positions, and sequence features—and internally evaluates the dataset branch once for every reference dataset. Repeated rows with the same transcript ID are checked to ensure those inputs are identical. The reference evaluation is part of the autograd graph during training; it is not a detached diagnostic.

5.4 Reference weights and the exact center

Reference weights are dataset-level constants and are unrelated to the local transcript reliability \(w_{dt}\) used by the loss. If \(r_d\) is a dataset's quality rank and \(R\) is the largest rank in the complete quality table, the configured base quality is

$$ q_d^{\mathrm{quality}}=\frac{R-r_d+1}{R}. $$

For weighting: quality_rank, the gamma-reference weight is

$$ u_d=\left(q_d^{\mathrm{quality}}\right)^p, \qquad p=\texttt{quality\_rank\_power}=1. $$

For weighting: equal, \(u_d=1\). Setting \(p=0\) also gives equal weights. These constants do not contain the current transcript's read density, coverage, target depth, or transcript reliability.

Let \(a^{\mathrm{ref}}_{dti}\) be the raw log-gamma produced by evaluating transcript \(t\) as reference dataset \(d\in\mathcal R\), and normalize the positive reference weights as \(\pi_d=u_d/\sum_eu_e\). Using the same valid-position mask for every reference evaluation, define

$$ c_{ti}=\sum_{d\in\mathcal R}\pi_d a^{\mathrm{ref}}_{dti},\qquad m_{dt}=\operatorname{mean}_{i:\,m_{ti}=1}a^{\mathrm{ref}}_{dti},\qquad \bar a_t=\sum_{d\in\mathcal R}\pi_d m_{dt}. $$

For any requested dataset \(d\)—inside or outside the panel—its own raw positional mean \(m^{\mathrm{req}}_{dt}\) is calculated and the final score is

$$ g_{dti}=a^{\mathrm{raw}}_{dti}-c_{ti}-m^{\mathrm{req}}_{dt}+\bar a_t, \qquad \gamma_{dti}=\exp(g_{dti}). $$

For the reference panel this gives both \(\sum_d\pi_d g_{dti}=0\) at every position and \(\operatorname{mean}_i g_{dti}=0\) for every dataset–transcript pair. Equivalently, both corresponding geometric means of gamma equal one. Means and weighted sums accumulate in float32 under mixed precision. There is no post-centering clamp and the reference evaluations remain in the autograd graph. Raw gamma magnitude is no longer interpretable; the meaningful object is its position-dependent shape under these gauges.

5.5 What happens when inference requests only one dataset

A one-row or one-dataset inference batch is still centered. The model internally evaluates the complete checkpointed reference panel for that transcript. It does not need a second requested dataset row in the batch.

Suppose a checkpoint was trained with ten reference datasets and inference requests only dataset \(A\). The model computes \(A\)'s requested raw log-gamma, separately evaluates all ten reference versions of the same transcript, calculates \(c_{ti}\), and returns \(\exp(a^{\mathrm{raw}}_{Ati}-c_{ti}-m_{At}+\bar a_t)\). The requested singleton therefore also has positional geometric mean one. The result is independent of batch size, row order, which partner datasets are requested, and how rows are partitioned over DDP ranks.

minimum_datasets: 2 refers to the size of the checkpointed reference panel, not the number of requested inference rows. Centering is skipped only when the stored panel contains fewer than two datasets. Thus a model newly configured and trained with exactly one experiment dataset has a one-dataset panel and leaves raw gamma unchanged, whereas a multi-dataset checkpoint can center a singleton inference request.

If an inference request uses a dataset outside the checkpoint's reference panel, the same fixed \(c_{ti}\) and \(\bar a_t\) are used while that requested dataset supplies its own \(m_{dt}\). The mathematical center is still well-defined and applied, but the diagnostic gamma_all_requested_in_reference becomes false. Such a result is an out-of-reference dataset extrapolation and should be interpreted accordingly.

6. Optimized loss

Plain language: the loss asks two complementary questions. NB2: “Are the predicted counts plausible for every raw replica?” PCC: “Does the predicted up-and-down shape match the arithmetic replica consensus?” Those answers become one score per transcript–dataset pair. Only then does transcript balancing combine pairs into a batch loss.

6.1 Consensus target and raw replica targets

The dataloader passes both the consensus target and a padded tensor of raw replicas. The consensus is the arithmetic mean

$$ y_{dti}=\frac{1}{R_{dt}}\sum_{r=1}^{R_{dt}}y_{dtri}. $$

The model's ordinary prediction \(\mu_{dti}\) uses the consensus-derived mean scale \(S_{dt}\) and the direct positive profile \(h_{dti}=\gamma_{dti}L^{\mathrm{bio}}_{ti}\). The product is not normalized to have positional mean one. For the optimized replica terms, the same unnormalized profile is reused but each raw replica receives its own observed mean scale:

$$ S_{dtr}=\max\left(\varepsilon,\frac{\sum_i m_{dtri}y_{dtri}} {\max(\sum_i m_{dtri},1)}\right), \qquad \mu_{dtri}=S_{dtr}h_{dti}. $$
Legacy field name: model outputs still expose this profile under extras["normalized_shape"] for compatibility with the replica loss and saved artifacts. With mass_conservation=false, its value is simply \(h_{dti}=\gamma_{dti}L^{\mathrm{bio}}_{ti}\); the name does not imply that a final mean-one normalization occurred.

Here \(\varepsilon=10^{-8}\) is the configured numerical floor. These two targets have deliberately different roles. NB2 is evaluated against every raw replica, preserving replicate-level count variation. Raw PCC and NB-VST PCC are shape terms and are evaluated once per pair against the arithmetic consensus \(y_{dti}\), using the ordinary consensus-scaled prediction \(\mu_{dti}=S_{dt}h_{dti}\). Neither the consensus prediction nor its replica-scaled versions are forced to conserve the corresponding target mass. A dataset with more replicas therefore does not receive more PCC terms.

6.2 Negative-binomial likelihood

Intuition: squared error assumes roughly constant noise. Ribosome counts are noisier when their mean is larger. NB2 explicitly allows that mean-dependent extra variation through \(\alpha\).

The only likelihood is NB2. For each valid position, the model output \(\ell_{dti}\), exposed in code as log_sigma, is clipped to the configured interval \([-5,1]\) and interpreted as the log dispersion. The functions \(\log(\cdot)\) and \(\exp(\cdot)\) are the natural logarithm and exponential, and \(\Gamma(\cdot)\) is the Gamma function. Define

$$ \alpha_{dti}=\exp(\ell_{dti}), \qquad \kappa_{dti}=\frac{1}{\alpha_{dti}}=\exp(-\ell_{dti}). $$

The NB2 variance is \(\operatorname{Var}(Y)=\mu+\alpha\mu^2\). For raw replica count \(y_{dtri}\) and prediction \(\mu_{dtri}\), the reported per-position negative log-likelihood is

$$ \begin{aligned} \ell^{\mathrm{NB}}_{dtri}={}& \log\Gamma(\kappa_{dti})-\log\Gamma(y_{dtri}+\kappa_{dti}) +\log\Gamma(y_{dtri}+1)\\ &-\kappa_{dti}\log\kappa_{dti} -y_{dtri}\log\mu_{dtri} +(\kappa_{dti}+y_{dtri})\log(\kappa_{dti}+\mu_{dtri}). \end{aligned} $$

The \(\log\Gamma(y+1)\) term is constant with respect to the model parameters but is retained in the reported NLL. Computation is forced to float32 with autocast disabled for this likelihood. Non-finite targets are masked; target counts are repaired to finite non-negative values before the formula, while invalid positions contribute zero.

6.3 Reduction across codon positions

For one raw replica, let \(V_{dtr}=\sum_i m_{dtri}\) be its number of valid positions. The active configuration uses nb_sequence_reduction: length_tempered, \(\gamma_L=0.75\), reference length \(L_0=1000\), and bounds \(0.5\) and \(2.0\). The sequence-level NB loss is

$$ \bar\ell^{\mathrm{NB}}_{dtr} =\frac{\sum_i m_{dtri}\ell^{\mathrm{NB}}_{dtri}} {\max(V_{dtr},1)}, \qquad \tau_{dtr}=\operatorname{clip}\left[ \left(\frac{V_{dtr}}{L_0}\right)^{1-\gamma_L},0.5,2.0\right], $$
$$ N_{dtr}=\bar\ell^{\mathrm{NB}}_{dtr}\tau_{dtr}. $$

Thus the code first averages over valid positions and then applies a bounded length factor. The pair-level NB term is the arithmetic mean over its \(R_{dt}\) valid raw replicas:

$$ N_{dt}=\frac{1}{R_{dt}}\sum_{r=1}^{R_{dt}}N_{dtr}. $$

A short transcript is not treated as a raw sum, and padding never increases its loss.

6.4 Consensus Pearson correlation terms

Intuition: PCC mostly judges shape. If prediction and target rise and fall together along the codons, PCC is high even when their vertical scale differs. That is why PCC is computed once against the cleaner replica consensus, while NB2 still checks every raw count profile.

Raw PCC compares the pair prediction \(x_{dti}=\mu_{dti}\) with the arithmetic replica consensus \(z_{dti}=y_{dti}\) over valid positions. In the following equation, \(m_i\) is shorthand for the consensus mask \(m_{dti}\), \(M=\sum_i m_i\), and \(\bar x\) and \(\bar z\) are mask-weighted means. The code evaluates a numerically stabilized Pearson correlation:

$$ \rho(x,z)= \frac{\operatorname{cov}_m(x,z)} {\sqrt{\left[\operatorname{var}_m(x)+\varepsilon\right] \left[\operatorname{var}_m(z)+\varepsilon\right]}}, \qquad \operatorname{cov}_m(x,z)=\frac1M\sum_i m_i(x_i-\bar x)(z_i-\bar z), \qquad \operatorname{var}_m(x)=\frac1M\sum_i m_i(x_i-\bar x)^2. $$

Adding \(\varepsilon\) to each variance keeps the derivative finite when a prediction is almost flat. For ordinary non-flat profiles it changes Pearson correlation only at numerical precision.

A transcript–dataset pair is PCC-valid only when the consensus target variance exceeds min_pcc_target_var: 1e-6. For a valid pair, the loss is \(1-\rho\). If the consensus is effectively constant, that PCC component is zero for the pair. There is no PCC reduction over replicas: each pair contributes at most one raw-PCC value and one NB-VST-PCC value. The position mask, not \(w_{dt}\), is used inside the correlation.

The NB-VST PCC applies the variance-stabilizing transform to both prediction and target. The \(\alpha\) in this branch is obtained from the same log-dispersion bounded to \([-5,1]\) as the NB likelihood; when pcc_detach_alpha: true, it is treated as a constant for gradients:

$$ T_{\alpha}(u)=\frac{2}{\sqrt{\alpha+\varepsilon}} \operatorname{asinh}\left(\sqrt{\alpha u+\varepsilon}\right), \qquad \rho_{\mathrm{VST}}=\rho\left(T_{\alpha}(\mu),T_{\alpha}(y)\right). $$

The configured pcc_detach_alpha: true detaches \(\alpha\) from this PCC branch, so the NB-VST correlation does not train the dispersion output. The two pair-level PCC losses are therefore

$$ P^{\mathrm{raw}}_{dt}=1-\rho\left(\mu_{dt},y_{dt}\right), \qquad P^{\mathrm{VST}}_{dt}=1-\rho\left( T_{\alpha_{dt}}(\mu_{dt}),T_{\alpha_{dt}}(y_{dt}) \right). $$

If the relevant consensus variance check fails, that component is defined as zero. Replica count affects the consensus estimate and the replica-NB average, but never creates several PCC terms or several outer dataset votes.

6.5 Gamma regularization

The model exposes a positive multiplicative correction \(\gamma_{dti}\) and its log \(g_{dti}=\log\gamma_{dti}\). The regularizer is computed once per transcript–dataset pair, not once per raw replica:

$$ G_{dt}=\frac{\sum_i m_{dti}g_{dti}^{2}} {\max(\sum_i m_{dti},1)}. $$

The active configuration sets gamma_reg_weight: 0.0. In that configuration the code skips the regularizer computation and its contribution is exactly zero. If the coefficient is later made positive, \(G_{dt}\) enters the same outer reduction as the data terms.

6.6 Pair loss and selectable sample reduction

After replica averaging for NB2 and one consensus evaluation for each PCC branch, one scalar is available for each retained pair. With the current coefficients \(c_N=1.0\), \(c_R=0.5\), \(c_V=0.5\), and \(c_G=0.0\), the exact pair loss is

$$ z_{dt}=c_N\,N_{dt}+c_R\,P^{\mathrm{raw}}_{dt} +c_V\,P^{\mathrm{VST}}_{dt}+c_G\,G_{dt}. $$

loss.sample_reduction selects exactly one of three reducers. All require finite strictly positive \(w_{dt}\); weights such as 1.25 or 3.0 are preserved without an upper clamp. Dataset-quality rank \(u_d\) is absent from every loss equation.

Default: transcript-balanced

$$ \boxed{ L_{\mathrm{transcript}}= \frac{1}{|\mathcal T_B|}\sum_{t\in\mathcal T_B} \frac{\sum_{d:(t,d)\in B}w_{dt}z_{dt}} {\sum_{d:(t,d)\in B}w_{dt}}. } $$

This is the recommended and checked-in mode. Local reliability decides how the positive dataset observations of one transcript divide that transcript's contribution. It does not multiply the transcript by support count, total weight, length, rank, or replica count. Every admitted transcript has one equal outer vote.

Ablation: dataset-balanced

$$ L_{\mathrm{dataset}}=\frac{1}{|\mathcal D_B|} \sum_{d\in\mathcal D_B} \frac{\sum_{t:(t,d)\in B}w_{dt}z_{dt}} {\sum_{t:(t,d)\in B}w_{dt}}. $$

Every represented dataset receives one equal outer vote; local reliability distributes that vote among its transcript rows. This preserves the previous active implementation as an ablation.

Ablation: global-weighted

$$ L_{\mathrm{global}}=\frac{\sum_{(t,d)\in B}w_{dt}z_{dt}} {\sum_{(t,d)\in B}w_{dt}}. $$

If \(S_t=\sum_d w_{dt}\) and \(\bar z_t=\sum_dw_{dt}z_{dt}/S_t\), then \(L_{\mathrm{global}}=\sum_t[S_t/\sum_uS_u]\bar z_t\). Global weighting therefore gives more outer mass to transcripts with more supporting datasets or larger total reliability. It equals transcript balancing when every transcript has the same total weight mass—for example, unit weights and exactly \(M\) datasets per transcript.

Toy example: transcript t1 has pair losses [1, 1] and weights [1.5, 1.5]; transcript t2 has losses [3, 3] and weights [0.5, 0.5]. Global weighting returns 1.5 because t1 has three times the total weight mass. Transcript balancing first gets means 1 and 3, then gives them equal votes, returning 2.0. This is the practical difference: reliability still chooses the mixture inside a transcript, but it does not decide how much that transcript matters compared with another transcript.

The vectorized reducer uses the collate-time integer transcript_group_index; it never regroups transcript strings in the training step. The same configured reducer is applied to every optimized pair-level term, including replica NB2, consensus raw PCC, consensus NB-VST PCC, and gamma regularization when enabled. Codon reduction occurs first; only NB2 then has a replica-reduction stage. Global parameter regularizers and diagnostics without one value per pair are not transcript-balanced.

Batch versus epoch: the formula above is evaluated for each physical batch. The optimizer receives the resulting batch scalar. Lightning subsequently combines batch gradients according to its unchanged automatic accumulation settings. With complete atomic groups, transcript balancing is exact inside a microbatch. It is exact over an accumulation window only when every microbatch contributes the same number of transcript groups; the runtime logs that count and its epoch coefficient of variation.

6.7 Complete current objective

Putting the definitions together, the default objective gives an equal outer vote to every admitted transcript. Within a transcript, its positive datasets are compared using the local median-normalized reliability weights. Every pair's NB2 term is averaged across its raw replicas, whereas both PCC terms are computed once from the replica consensus.

$$ \boxed{ L_B=\frac{1}{|\mathcal T_B|}\sum_{t\in\mathcal T_B} \frac{\displaystyle\sum_{d:(t,d)\in B}w_{dt} \left[N_{dt}+0.5P^{\mathrm{raw}}_{dt}+0.5P^{\mathrm{VST}}_{dt} \right]} {\displaystyle\sum_{d:(t,d)\in B}w_{dt}} } $$

The gamma term is omitted from this boxed expression because its current coefficient is zero. It is still part of the code path and becomes additive when gamma_reg_weight is positive. The raw and NB-VST consensus PCC terms are optimized; the additional unweighted mu_pcc, likelihood-PCC, and log1p-MSE values remain diagnostics.

Validation uses the configured mode for val_loss and, from the same detached pair losses without another forward pass, logs val/loss_global_weighted, val/loss_dataset_balanced, and val/loss_transcript_balanced. This makes the three objectives directly comparable while keeping the checkpoint monitor aligned with the configured reducer.

All metrics whose name contains mu_pcc are unweighted diagnostics. The global val_mu_pcc compatibility alias, explicit val_mu_pcc_unweighted, likelihood-mean variants, and per-dataset variants are ordinary arithmetic means over their contributing physical pairs; transcript reliability does not enter them. At validation-epoch end, pair PCC values are also averaged equally across the available datasets of each transcript. TensorBoard receives one compact histogram under val/mu_pcc_unweighted_by_transcript/distribution, plus count, mean, standard deviation, minimum, 5/25/50/75/95 percentiles, and maximum. This retains only one CPU float per validation transcript, performs no additional forward pass, and deduplicates the small number of validation batches that DDP may pad.
