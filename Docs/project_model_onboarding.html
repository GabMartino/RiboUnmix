RiboUnmix project onboarding and safe handoff

A code-oriented starting point for another developer or coding model. It explains where truth lives, which contracts must remain invariant, how the real-data experiments are launched and resumed, and how to distinguish a complete scientific result from a merely present file.

Operational snapshot: 7 September 2026

1. Read this before changing anything

The working tree may already contain valuable uncommitted work. Run git status --short first. Do not reset, delete, overwrite, or regenerate an existing experiment design unless the user explicitly asks for it.
  1. Read the user request and identify whether it concerns the production real model, a synthetic experiment, benchmarking, orchestration, resumption, or analysis.
  2. Inspect the relevant entrypoint, configuration, run manifest, and tests before editing.
  3. For an existing run, regard its saved artifacts as the source of truth. Do not infer its settings from today’s base YAML.
  4. Prefer dry-run and read-only artifact inspection before any GPU launch.
  5. Keep changes scoped. The repository contains large datasets and result trees that are not source files.
Source-of-truth order for an existing run: task resolved_config.yaml and launch_command.sh → task/global manifests → experiment orchestrator → current base YAML → explanatory documents. Several HTML pages are dated analyses and must not be silently reinterpreted as current executable behavior.

3. Minimal scientific contract

The active real experiments learn a sequence-only shared profile and a dataset-conditioned observation effect:

mu[d,t,i] = S[d,t] * L[t,i] * gamma[d,t,i]
mean_valid(L[t]) approximately 1
(L_{ti})Dataset-independent output of the biological sequence branch. Cross-model analyses compare this quantity on identical held-out transcript IDs.
(gamma_{dti})Dataset-specific multiplicative observation effect. Fixed-reference log-space centering defines its gauge.
(S_{dt})Target-derived mean scale. The usual prediction is therefore conditional profile prediction, not a sequence-only abundance forecast.
NB2 + PCCRaw replicas supervise the classical NB2 term; the arithmetic replica consensus supervises the shape-PCC terms.

Three unrelated meanings of “weight”

Symbol / settingPurposeDo not confuse it with
pi_d
gamma reference weighting		Defines the geometric reference center for gamma. The panel and Experiment-8 primary runs explicitly use equal dataset weights.Reliability in the training objective.
w_dt
sample reliability		Compares usable transcript–dataset observations inside the selected loss reduction. Real experiments normally fit its reference statistics on training IDs only.Subset selection or the gamma gauge.
QC variables / quality mismatchBalance panel or subset composition using observed data quality.Loss weights or gamma-reference weights.
Why equal gamma-reference weighting? The dataset-count experiment must change the amount of evidence without also changing the definition of the center through a quality-rank policy. Equal weighting fixes the policy, not the finite-panel estimand: changing which datasets are selected can still change the learned center.

4. Real-experiment invariants

Independent-panel convergence

  • The intended 114-dataset universe is partitioned into four dataset-disjoint panels of sizes differing by at most one.
  • Source families are indivisible and mutually exclusive across panels. An explicit non-empty source_identifier wins; otherwise the shared author_year-prefix inference is used.
  • All models are compared on the same common held-out transcripts, which never enter training.
  • Each panel has independent training, fixed-reference gamma centering over exactly its selected datasets, uniform pi_d, classical standard_nb, and best-validation-loss checkpoint selection.

Experiment 8

  • For N=2,5,10,20,40, the primary comparisons are within three designated A/B pairs; A and B are dataset- and source-family-disjoint.
  • N=80 has three quality-matched subsets and is used for convergence to the empirical N=114 reference, not the primary disjoint statistic.
  • N=114 has one full-collection model. It is a convergence reference, not biological ground truth.
  • Subsets preserve source-family atomicity and target exact dataset cardinality. Selection minimizes mismatch to the full pool using standardized read density, positive-codon coverage, eligible-transcript count, and replica PCC when sufficiently available.
  • All overlap is measured. Never infer the main N trend from increasingly overlapping arbitrary subsets.
  • subset_seed selects data; training_seed controls optimization. The primary matrix holds the training seed fixed.
Reliability leakage rule: fit per-dataset reliability reference statistics from training transcripts only, freeze them, and reuse them for validation/test. The transcript–dataset reliability formula itself should remain unchanged.

5. Configuration and batching

Never describe a run from the base YAML alone. The checked-out base configuration currently contains defaults that the real scientific orchestrators override—for example, the real panel/Experiment-8 commands set model.mass_conservation=false and equal gamma-reference weighting. Read the task’s saved command and resolved configuration.

The current A100-64GB real launch profile records these values in each task:

Logical per-dataset quotadata.batch_size=32
Execution pair-row capmax_pair_rows_per_forward=512
Execution padded-token capmax_padded_codon_tokens_per_forward=256000
Optimizer target32 unique transcript groups per optimizer step, resolved by grouped accumulation
Numericsbf16-mixed, raw log-gamma bound 8, gradient norm clipping at the complete optimizer-update boundary
Lossstandard_nb, nb_mean_gradient_beta=0, transcript-balanced reduction

Logical batching chooses complete transcript groups and defines the objective membership. Execution microbatching splits that logical work between complete groups to bound GPU memory. Gradient accumulation targets the chosen number of unique transcripts per optimizer update. Reference chunking only partitions fixed-reference gamma evaluation and must retain every chunk in autograd.

Execution caps and reference chunk size may be changed for memory/throughput only after checking their invariance tests. Changing data.batch_size, the optimizer target, the sampler, loss reduction, training seed, selected datasets, or split changes training dynamics or the scientific design.

7. Safe continuation and HPC behavior

For an unfinished real experiment, use resume_real_experiment_from_checkpoints.py. It reuses every task’s saved design, retargets portable paths, skips completed predictions, inspects checkpoints on CPU, rejects truncated files, and queues one independent process per visible GPU.

  • Exact full-state resume: checkpoint contains model, Adam, scheduler, epoch, and global-step state.
  • Weights-only warm start: not exact. It requires explicit --allow-weights-only-warm-resume and must be reported as a limitation.
  • Fresh start: no usable checkpoint exists. It keeps the frozen subset and split but restarts optimization.
# Audit only: no training
python resume_real_experiment_from_checkpoints.py \
  --run-root /path/to/existing/run \
  --gpus 0,1 --dry-run

# Select only Experiment-8 N=40,80,114 plus one exact task
python resume_real_experiment_from_checkpoints.py \
  --run-root /path/to/existing/exp8 \
  --gpus 0,1 --dataset-sizes 40,80,114 \
  --include-run-ids real_exp8_N010_pair01_B \
  --schedule-order explicit-first-largest --dry-run
N=114 CPU-memory exception: a spawned worker must pickle a very large already-materialized dataset. The observed _pickle.UnpicklingError: pickle data was truncated is avoided by running N=114 with data.num_workers=0. This changes data delivery, not the model, logical batch, objective, or optimizer. The dedicated resume_real_exp8_N114_256G.slurm requests one GPU, 256 GB host memory, and selects only N=114.
sbatch --export=ALL,RUN_ROOT=/path/to/existing/exp8 \
  resume_real_exp8_N114_256G.slurm

8. Known failure signatures

SignatureLikely causeSafe response
No supported gpu backend foundThe child has no valid CUDA visibility, was launched outside a GPU allocation, or inherited an unsuitable CUDA check state.Verify srun nvidia-smi, Slurm GPU allocation, CUDA_VISIBLE_DEVICES, environment activation, and one queue per physical GPU.
CUDA out of memoryAnother process occupies the GPU, or execution/reference chunks are too large.Check nvidia-smi first. Do not run two tasks on one GPU. Then reduce execution-only caps or reference chunk size without changing logical batching.
Non-finite gradientsNumerical instability. Historical checks ran after norm clipping, which can contaminate otherwise finite branches and obscure the source.Preserve the bound and BF16 profile; inspect the new per-backward context before clipping. Use DETECT_ANOMALY=1 with the N=114 resume wrapper to trace the originating backward operation. See the N=114 investigation. Never silently discard a complete accumulated update.
Training stopped in the middle of a logical batchThe epoch ended or interruption occurred before all execution chunks/accumulated logical batches completed.Use a compatible full-state checkpoint and the current microbatch implementation; do not apply a partial logical-batch gradient.
Resume design hash mismatchThe requested design/config differs from the stored subset manifest.Do not force stale reuse. Continue from the frozen saved launch_command.sh, or create a clearly new run.
File name too long or ENOENT naming the entire commandA shell-formatted command was passed to Popen as one string.Use the current resume helper, which parses with shlex and executes an argv list with shell=False.
Parquet magic bytes not foundEmpty, truncated, or non-Parquet output despite the expected suffix.Quarantine/regenerate that prediction from the selected checkpoint; do not count it as complete.
_pickle.UnpicklingError: pickle data was truncatedSpawn-worker serialization/IPC failure for the large in-memory N=114 dataset.Use data.num_workers=0 and sufficient host RAM for the N=114 retry.

9. Analysis rules

  • Use only best-validation-loss predictions for the primary real experiments.
  • Align by transcript ID and use identical valid-position masks. Never compare rows by incidental file order.
  • Verify (L_t) mean-one normalization and vector length before calculating PCC, Spearman, or RMSE.
  • Preserve hierarchy: subset/panel → model → transcript → codon. Do not treat millions of codon positions as independent experimental replicates.
  • Label incomplete output as partial. Panel analysis needs at least two valid panels and is final only with all four. Full-reference Experiment-8 convergence requires N=114.
  • Copied runtime manifests may contain stale absolute Leonardo paths; current analyzers remap uniquely named artifacts inside the copied task directory.
# These have useful local defaults, but explicit paths are safer for publication
python analyses/analyze_real_panel_convergence.py \

11. What a useful future handoff should report

  1. Exact files changed and why.
  2. Which scientific and execution contracts were preserved.
  3. Run root, run IDs, selected datasets, seeds, and design/ID hashes affected.
  4. Whether a continuation was exact full-state, weights-only, or fresh.
  5. Tests, help commands, dry-runs, and artifact validations executed.
  6. Any partial results, stale paths, corrupt artifacts, missing predictions, or unresolved cluster constraints.
Compact rule: preserve the scientific design, use saved run provenance for existing experiments, distinguish logical mathematics from execution-only chunking, and never call a run complete until its best-loss checkpoint and readable common-test shared-profile artifact agree with the manifests.
