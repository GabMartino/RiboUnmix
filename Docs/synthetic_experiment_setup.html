RiboUnmix synthetic bias and read-depth experiments

What the data contain, how they are prepared, how the training panels are assembled, what is optimized, and how shared-profile, gamma, and dispersion recovery are evaluated.

Purpose and source of truth

The synthetic suite asks whether a model can separate one shared, deterministic biological profile from dataset-specific, programmed sequence biases while the observations become more or less noisy with read depth.

1 shared truthMean-one latent kinetic profile \(K_{ti}\), one profile per transcript.
10 programmed biasesEight dinucleotide contexts plus AU-rich and GC-rich window conditions.
3 read depths0.25, 2, and 20 expected unbiased reads per codon.
2 raw replicasNB2 count targets, with a consensus used for PCC diagnostics and terms.
Scope of this page.

It deliberately distinguishes current executable behavior from older reports. The upstream synthetic-data generator is not checked into this repository; generator details below come only from the Parquet metadata and the code that consumes the files.

Synthetic data: what was generated

Shared kinetic reference

Datasets/Synthetic_data/artificial_ground_truth_kinetics_target_mean_one.parquet has 19,290 long-format rows with columns sample, transcript_id, and rib_profile. Its metadata says that the values are programmed P-site residence times divided by the within-transcript mean; finite-read sampling, Gillespie sampling, and TASEP exclusion are all false.

$$K_{ti}=\frac{k_{ti}}{\frac{1}{n_t}\sum_{j=1}^{n_t}k_{tj}},\qquad \frac{1}{n_t}\sum_i K_{ti}=1.$$

Thus \(K\) is the only direct reference for recovery of the shared mean-one biological profile \(L_{bio}\). It is not an observation target in the loss.

From raw files to replica-aware training pairs

The executable preparation script is Datasets/data/weight_synthetic_riboseq_codon_replicas.py. For every depth and observation it reads a raw long-format count parquet, pivots the three sample rows into one transcript–dataset row, aligns it to the MANE sequence table, and delegates filtering/weighting to weight_hek_riboseq_codon_replicas.py.

The current MANE sequence parquet has 19,283 transcripts. The raw synthetic truth has 19,290, so seven raw IDs are absent from the sequence table. A representative weighted 0.25-depth bias parquet has 19,283 rows, two replicas per row, no retained zero-sum consensus rows, and a median stored weight of one.

Subtle but important consensus fact.

The preprocessing script stores the source mean row in ribo. The datamodule checks that stored consensus for eligibility, then builds its active ribo_profiles as the arithmetic mean of rep1 and rep2. Consequently NB2 sees the raw replicas, while both PCC terms see the arithmetic replica consensus—not a third independent draw and not necessarily the source's integerized mean cell.

Pair-local filtering and transcript reliability weights

Filtering is transcript–dataset local. A row is retained only when the stored consensus profile is non-empty, finite, non-negative, has positive total reads, and has positive codon coverage. Ineligible rows are physically absent from the weighted parquet; a zero-weight retained row is not supported.

For retained pair \((d,t)\), let \(n_{dt}\) be its aligned profile length, \(D_{dt}\) its read density, and \(C_{dt}\) its positive-codon coverage:

$$D_{dt}=\frac{\sum_i y_{dti}}{n_{dt}},\qquad C_{dt}=\frac{\#\{i:y_{dti}>0\}}{n_{dt}},\qquad \tau_d=\operatorname{median}_{t:\,\mathrm{eligible}}D_{dt}.$$

The currently default snr_depth_coverage weighting mode is:

$$q_{dt}=\frac{\sqrt{D_{dt}}}{\sqrt{D_{dt}}+\sqrt{\tau_d}},\qquad r_{dt}=0.70\,q_{dt}+0.30\,C_{dt},\qquad w_{dt}=\frac{r_{dt}}{\operatorname{median}_{t:\,\mathrm{eligible}}r_{dt}}.$$

The final \(w_{dt}\) is stored as float32 and is deliberately not clipped to one. It is a local observation reliability measure, not a global dataset-quality score. The legacy coverage/density percentile formula remains available in the generic HEK weighting code, but it is not the default synthetic preprocessing mode.

Methodological caveat for final locked studies.

Both \(\tau_d\) and the median normalizer are currently fitted over the full eligible processed parquet before train/validation assignment. They therefore use validation observations. This does not insert latent truth into training, but a strict final protocol should fit these references on training IDs only and freeze them for validation.

Coordinates, terminal padding, and long transcripts

Raw synthetic profiles use 0-based P-site codon coordinates and exclude the terminal boundary. The MANE sequence table includes the terminal codon. During preprocessing one zero is appended to every synthetic consensus and replica profile to match the sequence length. This makes batch shapes consistent, but it means the terminal padded entry is not an observed synthetic count.

$$\text{raw synthetic coordinates: }0,\ldots,L-1\quad\longrightarrow\quad\text{model profile: }0,\ldots,L-1,L_{\mathrm{terminal}}.$$

To avoid extremely long padded batches, the current synthetic configuration sets data.max_cds_codons=4000. It removes a whole transcript before split assignment; it never crops one. On the current MANE table this removes 79 of 19,283 transcripts, leaving 19,204 eligible sequences with longest retained CDS length 3,998 codons. This policy preserves the start/stop alignment and the transcript-wide gamma gauge.

Recovery domain.

Modern shared-L and gamma recovery scripts compare only the physical CDS interior, \(5\le i<L-5\). The final padded stop is absent after alignment to the raw latent/bias profiles, and the first/last five physical codons are excluded because boundary RPF features can depend on sequence outside the CDS-only model input.

Train/validation split

There is no independent test partition in the current synthetic configuration. It creates one transcript-level training partition and one fixed transcript-level validation partition.

$$\mathcal{V}_{\mathrm{candidate}}=\left\{t:\ t\text{ is sequence-eligible and has one retained positive-weight row in every master-universe dataset}\right\}.$$

For a within-depth panel, split.master_dataset_universe=all resolves to all 11 processed observations for that depth: the ten biased datasets plus the unbiased finite-count artificial_ground_truth. The unbiased observation helps define the fixed validation eligibility panel but is not included in the ten-bias training panels.

For every common candidate, the split-only score is the ordinary median across local weights. Candidate IDs are sorted by this score, assigned rank-quantile bins, jointly stratified with the CSS-count category from the sequence table, and sampled with NumPy's seeded generator. The exact split is saved in a split_manifest_*.json beside each run.

$$s_t=\operatorname{median}_{d\in\mathrm{master}}w_{dt},\qquad |\mathcal{V}|=\operatorname{round}\!\left(0.10\,|\mathcal{V}_{\mathrm{candidate}}|\right).$$

What is held fixed.

Within one depth, all cumulative panels use the same 11-dataset master universe, seed, length filter, and therefore the same validation transcript IDs. Across depths, validation IDs can change because read depth changes the local reliability ordering. The local cross-depth series instead makes all 30 aliases its master universe, so its cumulative cross-depth panels share one different validation panel.

Why the panels begin at two datasets.

data.minimum_positive_datasets_per_transcript=2 and train_sampling_strategy=transcript_grouped_multidataset_pairs require every training transcript group to contain at least two selected, positive observations. This is needed for the shared/decomposition setting and avoids singleton groups in the training objective.

Experiment family B: inter-depth comparisons and gamma reference weighting

The intended comparison combines the same bias at shallow, intermediate, and deep read depth, then asks whether equal gamma-centering weights differ from a depth-quality-ranked reference. The three aliases for a bias are, for example, artificial_bias_3prime_aa_0p25_per_codon, ..._2_per_codon, and ..._20_per_codon.

For ranked centering, temporary per-task metadata assigns ranks 3, 2, and 1 to 0.25, 2, and 20 reads/codon respectively. The dataloader converts rank to a positive quality score then the model normalizes it over the reference panel:

$$u_d=\frac{R_{\max}-R_d+1}{R_{\max}},\qquad \pi_d=\frac{u_d^{p}}{\sum_{r\in\mathrm{reference}}u_r^{p}}.$$

At power \(p=1\), the raw quality scores are \((1/3,2/3,1)\), and the normalized gamma-reference weights are \((1/6,1/3,1/2)\) for shallow, intermediate, and deep observations. The equal condition ignores quality ranks and uses \((1/3,1/3,1/3)\).

Rank affects gamma centering only.

It does not multiply the likelihood, PCC loss, local transcript reliability weight, or outer transcript-balanced loss. This is intentional: rank supplies the reference gauge, while \(w_{dt}\) describes local observation reliability inside the loss.

Grouped batches, accumulation, and memory-safe execution

The sampler builds an atomic transcript group \(G_t=\{(t,d):\text{selected positive pair exists}\}\). A group is admitted only if it has at least two distinct selected datasets. It is never split by the logical batch planner.

$$\texttt{data.batch\_size}=32\quad\text{means at most 32 pair rows per represented dataset in one logical batch, not 32 pair rows total.}$$

With \(D\) complete datasets, a typical full logical batch has 32 transcript groups and up to \(32D\) transcript–dataset rows. It is packed by descending sequence length, shuffled at the batch level, and uses one deterministic epoch plan per seed/epoch.

Execution microbatching splits a logical batch only between whole transcript groups. The model backpropagates each execution chunk immediately, scaling its transcript-balanced loss by its fraction of logical groups (and the logical accumulation factor). As a result, when all chunks are completed, their gradient sum equals the original logical transcript-balanced objective. It changes memory use and the number of forwards, not the intended gamma center or logical loss membership.

$$\nabla\mathcal{L}_{\mathrm{logical}}=\sum_{c\in\mathrm{chunks}}\frac{|G_c|}{|G_{\mathrm{logical}}|}\nabla\mathcal{L}_c.$$
Single-process restriction.

With execution microbatching enabled, trainer.accumulate_grad_batches is set to one because manual logical accumulation is performed in the Lightning module. It is explicitly incompatible with DDP/multi-process training. To use multiple GPUs, run independent experiments on different GPUs through GPU_DEVICES=0,1,..., not one DDP experiment.

What the model factorizes

The biological branch is a two-layer bidirectional GRU with hidden size 256. It produces a positive mean-one shared profile \(L_{ti}\). The separate dataset-bias branch is a two-layer bidirectional GRU with hidden size 128, dataset and codon embeddings, nucleotide/amino-acid embeddings, relative/start/stop positional features, and a gamma head. It also has a separate dispersion head.

For pair \((d,t)\), the scale \(S_{dt}\) is the mean of the current consensus target. In the current baseline, mass conservation is disabled, so the mean prediction is:

$$S_{dt}=\frac{1}{n_t}\sum_i\bar{Y}_{dti},\qquad \mu_{dti}=S_{dt}\,\gamma_{dti}\,L_{ti},\qquad \frac{1}{n_t}\sum_iL_{ti}=1.$$

Therefore \(\mu\) is intentionally an observation-level, bias-containing prediction; it should not be compared directly with the unbiased kinetic truth. The special mass_conservation=true ablation would divide \(\gamma L\) by its valid-position mean before multiplication by \(S\), but the main local synthetic matrix explicitly locks model.mass_conservation=false.

Fixed-reference gamma centering

Raw dataset scores \(a_{dti}\) are bounded before centering by raw_log_gamma_bound=8.0. The model then applies a two-axis log-space gauge. Let \(\pi_d\) be equal or quality-ranked normalized reference weights, \(c_{ti}\) their position-wise reference mean, \(m_{dt}\) the raw score's valid-position mean, and \(\bar a_t\) the weighted mean of those pair means:

$$c_{ti}=\sum_{d\in R}\pi_d a_{dti},\qquad m_{dt}=\frac{1}{n_t}\sum_i a_{dti},\qquad \bar a_t=\sum_{d\in R}\pi_d m_{dt},$$ $$g_{dti}=a_{dti}-c_{ti}-m_{dt}+\bar a_t,\qquad \gamma_{dti}=\exp(g_{dti}).$$

For the active geometric-mean gauge this satisfies:

$$\sum_{d\in R}\pi_d g_{dti}=0\quad\forall(t,i),\qquad \frac{1}{n_t}\sum_i g_{dti}=0\quad\forall(d,t).$$

Fixed-reference centering evaluates every reference dataset deterministically for each transcript. It is therefore invariant to the requested row order and to execution chunking. Recovery analysis must apply exactly this same two-axis gauge to the programmed multiplier \(b\); raw \(b\) and raw \(\gamma\) are not directly comparable.

Current NB2 and PCC objective

The current synthetic baseline is loss.experiment_mode=standard_nb, model.alpha_mode=learned, and loss.nb_mean_gradient_beta=0.0. Dispersion is position-specific:

$$\alpha_{dti}=\exp\!\left(\operatorname{clip}(\ell_{dti},-5,1)\right),\qquad \operatorname{Var}(Y_{dti})=\mu_{dti}+\alpha_{dti}\mu_{dti}^{2}.$$

The alpha head receives a detached version of the dataset-conditioned context: alpha gradients train the alpha head but do not reshape the gamma encoder through that route. The gamma/NB mean path remains attached. The configured alpha learning-rate scale is 0.1 times lr_rest.

For pair \((d,t)\), with raw replicas \(Y_{dtr}\), arithmetic replica consensus \(\bar{Y}_{dt}\), valid-position NB sequence loss \(\ell^{NB}_{dtr}\), and valid-position gamma regularizer \(R^{\gamma}_{dt}\), the active pair loss is:

$$z_{dt}=1.0\left[\frac{1}{2}\sum_{r=1}^{2}\ell^{NB}_{dtr}\right]+0.5\,[1-\operatorname{PCC}(\mu_{dt},\bar Y_{dt})]+0.5\,[1-\operatorname{PCC}(T_\alpha(\mu_{dt}),T_\alpha(\bar Y_{dt}))]+0.0\,R^\gamma_{dt}.$$

The transform used by the second PCC term is the NB variance-stabilizing transform:

$$T_\alpha(x)=\frac{2}{\sqrt{\alpha+\varepsilon}}\operatorname{asinh}\!\left(\sqrt{\alpha x+\varepsilon}\right).$$

NB2 is first reduced within a sequence using the active length-tempered factor:

$$\ell^{NB}_{dtr}=\overline{\ell}^{NB}_{dtr}\;\operatorname{clip}\!\left[\left(\frac{n_t}{1000}\right)^{1-0.75},\,0.5,\,2.0\right].$$

A zero coefficient skips computation of its corresponding term. The baseline uses raw replica NB2 plus raw and NB-VST consensus PCC, while gamma regularization is off.

Transcript-balanced outer reduction

The active reducer is sample_reduction=transcript_balanced. It uses reliability weights only to divide one transcript's vote among its available datasets, then gives every transcript equal outer mass:

$$\mathcal{L}_t=\frac{\sum_{d\in G_t}w_{dt}z_{dt}}{\sum_{d\in G_t}w_{dt}},\qquad \mathcal{L}_{\mathrm{batch}}=\frac{1}{|\mathcal{T}_{\mathrm{batch}}|}\sum_{t\in\mathcal{T}_{\mathrm{batch}}}\mathcal{L}_t.$$

Thus an observation's local weight changes its share within a transcript, but neither high-depth transcripts nor transcripts available in more selected datasets receive more total outer loss mass. Dataset quality ranks do not enter this reduction.

Recovery evaluation and which scripts to use

Shared biological profile

The modern ablation-recovery script, analyses/synthetic_gamma_ablation_lbio_recovery.py, evaluates \(L_{bio}\) against deterministic \(K\) over the CDS interior. It reports per-transcript Pearson correlation, Spearman correlation, and shape RMSE after mean-one normalization. Observed consensus comparisons are secondary diagnostics only: they contain both finite-count noise and the programmed dataset bias.

$$e^L_{ti}=\log(L_{ti}+\varepsilon)-\log(K_{ti}+\varepsilon),\qquad 5\le i<L-5.$$

Gamma recovery

analyses/analyze_synthetic_gamma_recovery.py reads added_bias, forms \(b=1+\texttt{added\_bias}\), and applies the same joint reference/positional log gauge to the truth and learned score. It must be invoked with --checkpoint-variant best_val_loss for the scientific selection rule; its historical default is best_pcc.

Gamma compensation and alpha absorption

analyses/analyze_synthetic_gamma_compensation.py accepts only explicit predictions_main_val_best_val_loss_*.parquet artifacts. It evaluates whether missed systematic gamma is accompanied by positive \(L\) error, increased learned alpha, both, or neither, and uses the raw replicas to distinguish empirical replica disagreement from apparent alpha inflation. It reuses the gamma-recovery gauge implementation rather than independently redefining the coordinate/gauge system.

Two older defaults need an explicit override.

analyses/analyze_synthetic_recovery.py defaults to selecting val_mu_pcc; pass --selection-metric val_loss for minimum-loss evidence. analyses/analyze_synthetic_gamma_recovery.py defaults to best_pcc; pass --checkpoint-variant best_val_loss. The numbered 13_gamma_ablation_recovery.py and compensation workflow are the safer current choices for the stated best-loss policy.

The in-training synthetic validation metrics under val/synthetic_ground_truth/... are diagnostic only. They never contribute to the loss or checkpoint monitor. They are intentionally skipped when a distributed process group is initialized to avoid a second potentially misordered collective stream.

Separate alpha-causality suite

run_synthetic_alpha_causality_local.sh is a controlled A/B/C suite, separate from the main 47-task matrix. Its default panel is 0.25 reads/codon with five biases: 3′ AA, 3′ CC, 3′ GG, GC>0.7, and AU>0.7. It uses only the minimum-validation-loss prediction checkpoint.

Interpretation safeguards and known limitations

  1. Do not read \(\mu\) as recovery of \(K\). \(\mu\) should retain the programmed bias; \(L_{bio}\) is the shared-profile output to compare with \(K\).
  2. Do not compare raw gamma with raw bias multiplier. Both must be placed in the same fixed-reference and positional log gauge.
  3. Use the interior domain. The raw profiles exclude the terminal boundary and the first/last five codons are excluded from modern recovery metrics.
  4. Do not conflate data count with bias identity. Cumulative panels add a particular new bias each time.
  5. Do not compare local and Slurm inter-depth results as if they were the same design. Their selected sets, split universe, and current execution compatibility differ.
  6. Weight fitting is pre-split. It uses full eligible data and should be made train-only for a final leakage-controlled protocol.
  7. Current synthetic evaluation is validation-only. A test split is not currently created.
